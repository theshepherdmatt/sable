# Sable -- Config & Script File Reference

A repair agent will typically only ever need to touch the files marked
**safe to edit**. Files marked **do not touch** are core system config,
generated/regenerated files, or things that require careful validation
(sudoers) that a casual edit can silently break.

| Path | What it controls | Safe to edit? | Why |
|---|---|---|---|
| `config/settings.json` | Live USER preferences: display screen/theme/brightness/rotation, clock format, screensaver timings, IR enable + profile, button assignments, DAC input hint. Single source of truth (`src/sable/settings.py`). | **Yes** | This is exactly the file the Volumio web settings page reads/writes. Gitignored (per-machine). Edited via `Settings.set()` (atomic write) at runtime, but a repair agent can also edit it directly with the app stopped, or push a change and restart the service. |
| `config/settings.default.json` | The DEFAULTS baked into git (fallback when `settings.json` is absent). | **Caution** | Editing this changes the out-of-box defaults for every future install, not just this machine. Only touch if the user explicitly wants to change a *default*, not a live preference -- normally edit `settings.json` instead. |
| `config/hardware.json` | Per-machine PHYSICAL WIRING overrides (OLED DC/RST/BLANK pins, rotary CLK/DT/SW pins, rotary reverse flag, MCP23017 address/led_reverse). Gitignored. See `config/hardware.example.json` for the template + `src/sable/hardware.py` for defaults. | **Yes** | This is the intended mechanism for fixing GPIO conflicts / wiring differences without touching source code. Only include the keys that actually differ from defaults. |
| `config/hardware.example.json` | Documented TEMPLATE for `hardware.json` (the EVO Sabre wiring, as an example). Committed to git. | **Do not touch** unless improving the template/comments | It's documentation, not live config. Copy it to `config/hardware.json` and edit the copy instead. |
| `config/cava.conf` / `config/cava-live.conf` | CAVA (spectrum analyser) tuning: bar count, sensitivity, input/output fifo paths. `cava-live.conf` is the PRODUCTION config (real MPD audio); `cava.conf` is the bench/test-tone config. | **Caution** | Safe to tune bar count / sensitivity. Do NOT change the fifo paths (`/tmp/cava.fifo`, `/tmp/sable-display.fifo`) without also checking `src/sable/app.py`'s `_MPD_PCM_FIFO`/`_SABLE_DISPLAY_FIFO` constants and `src/sable/display/fifo_meter.py`'s `CAVA_FIFO`/`DISPLAY_FIFO` -- they must match. |
| `config/lirc/lircd.conf` | The CANONICAL/fallback IR remote button-code map, used if the selected profile is missing. | **Yes, if replacing the remote** | README documents replacing this file (keeping `KEY_*` names) as the supported way to add a new/different remote. |
| `config/lirc/lirc_options.conf` | LIRC daemon options (socket path, driver). Copied to `/etc/lirc/lirc_options.conf` by the installer. | **Do not touch** unless you understand LIRC | Sable's IR listener depends on `output=/run/lirc/lircd` specifically (`src/sable/inputs/ir.py:37`). Changing this can silently break IR. |
| `config/lirc/profiles/<RemoteName>/lircd.conf` | Vendored library of remote profiles (Volumio's `ir_controller` set), selectable via `ir.profile` in settings. | **Yes, to add a new profile** | Add a new directory here matching the naming convention; select it via `settings.json`'s `ir.profile`. |
| `plugin/plugin.json` | Volumio plugin metadata: id, name, version, supported OS/arch, `volumio_version` requirement. | **Do not touch** | Changing `id`/`category`/`plugin_type` can break how Volumio's plugin manager tracks the install. Version bumps are fine if the user is doing a real release. |
| `plugin/config.json`, `plugin/UIConfig.json` | The Volumio settings-PAGE definition (what fields show in the web UI) and its current values. | **Caution** | `UIConfig.json` is regenerated/pushed by `volumio plugin refresh` from `plugin/` sources — hand-editing may be overwritten. Prefer editing the Node source that generates it (`plugin/index.js`) if changing what the settings page offers. |
| `plugin/index.js` | The Volumio plugin's Node.js backend: renders the settings page, handles saves, includes the sudo-gated IR pin/profile switch logic. | **Caution, higher risk** | This is real application logic (not just data). A syntax error here breaks the Volumio plugin subsystem generally, not just Sable's own service. Test with `node -c plugin/index.js` (syntax check) before deploying, and always rebuild via `tools/build-plugin.sh` + `volumio plugin refresh` (see README "Updating"). |
| `systemd/sable.service` | The main service unit: what command starts Sable, restart policy, working directory, environment (`PYTHONPATH`). Installed to `/etc/systemd/system/sable.service` by `install.sh`. | **Caution** | Safe to read to understand behaviour. Editing it changes fundamental process supervision (e.g. `--stage`, `Restart=` policy) -- a mistake here can crash-loop the whole display. If changed, must re-run `install.sh` (or manually `cp` + `daemon-reload`) and reboot. |
| `systemd/sable-controls.service.tmpl`, `sable-display.service.tmpl`, `sable-ir.service.tmpl`, `sable-moode.service.tmpl` | Templates for an alternate split-process architecture (placeholders `@ROOT@`/`@PYTHON@` substituted at install time). | **Confirmed not live on the reference Pi** | Verified via live SSH audit (2026-08-19): only `sable.service` is installed/running on the standard Volumio deployment; `sable-controls.service` etc. are not installed unit files at all. The single `sable.service` process (`--stage full`) owns buttons/LEDs/IR in-process (`src/sable/inputs/buttons.py`, `inputs/ir.py`), NOT via `src/sable/controls.py` (which defines a `CONTROLS_SOCKET` that `src/sable/volumio/listener.py` optionally fans status out to, but silently no-ops if nothing's listening -- confirmed harmless, not a crash). Editing these `.tmpl` files has **no effect** on a standard install; they only matter if someone deliberately switches to the split-process architecture (unclear if that path is still supported/tested -- ask the maintainer before assuming so). |
| `install.sh`, `install-moode.sh` | The installers: apt/pip deps, kernel overlay lines in `/boot/userconfig.txt`, MPD fifo output, systemd units, the `/etc/sudoers.d/sable` rule. Idempotent -- safe to re-run. | **Caution, but re-running is safe** | Do not hand-edit casually, but DO re-run the whole script if config it manages (overlays, sudoers, MPD fifo, service files) needs to be reapplied -- it's designed to be idempotent and safe to re-run (`README.md:126-127`). |
| `bin/sable-set-ir-pin.sh` | Helper script (root) that rewrites the `gpio-ir` overlay's pin number in `/boot/userconfig.txt`. Invoked by the plugin's Node backend via the sudoers rule, or can be run directly. | **Yes to run, caution to edit** | Safe and intended to be RUN (`sudo bin/sable-set-ir-pin.sh <pin>`) to fix an IR/GPIO conflict. Editing the script itself should be rare. |
| `/boot/userconfig.txt` (outside the repo, on the Pi's boot partition) | Raspberry Pi kernel overlay config: `dtparam=spi=on`, `dtparam=i2c_arm=on`, `dtoverlay=gpio-ir,gpio_pin=N`, `dtoverlay=gpio-shutdown,gpio_pin=17,...`. | **Caution, core system file** | Outside this repo entirely. Sable's installer appends to it; `bin/sable-set-ir-pin.sh` rewrites one line. Any other line in this file may belong to Volumio/moOde or other hardware (DAC HAT overlays!) -- do not remove or reorder lines you didn't add, and always confirm with the user before touching lines unrelated to Sable. On Bookworm the LIVE file may actually be `/boot/firmware/config.txt` (README.md:228 flags this moOde-specific gotcha). |
| `/etc/sudoers.d/sable` (outside the repo) | Passwordless sudo rule for the specific commands Sable's Node plugin and shutdown sequence need (`systemctl start/stop/restart sable.service`, `poweroff`, the IR pin helper, lircd restart). Regenerated by `install.sh` on every run. | **Do not hand-edit** | Always regenerate via re-running `install.sh` (which validates with `visudo -cf` before installing) rather than editing this file directly -- a malformed sudoers file can be refused by the system entirely. |
| `requirements.txt`, `requirements-moode.txt` | Pure-Python pip dependencies (installed by the installer with `--break-system-packages`, no venv). | **Caution** | Adding a new pip dependency here means the installer must be re-run on the Pi; removing one could break the app at import time. Check `install.sh:62-66`'s import smoke-test list if changing this. |
| `tests/fixtures/rp_paused.json` | A captured real Volumio "paused" pushState payload, used by tests/dev fixture runs. | **Do not touch casually** | Changing this changes what several tests/dev tools assert against; treat as test data, not config. |

## Files this repair agent will almost never need

`assets/` (icons/artwork), `plugin/sableapp/` (a mirrored copy of `src/`,
`config/`, etc. assembled by `tools/build-plugin.sh` for plugin packaging --
**edit the top-level `src/`/`config/` originals, not this mirrored copy; it
gets regenerated**), `plugin/package.json` / `package-lock.json` (Node
dependency lockfile for the plugin wrapper).
